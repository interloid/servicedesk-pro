## Membership and user write fix, 2026-11-04

`20261104120000_restrict_membership_and_user_writes.sql` is in the working tree, **not committed and not applied on live**. It removes client insert, update and delete on `memberships`, removes `users_delete`, and limits `users_update` to the caller's own row.

It also closes two paths the original findings did not list: a Tenant Admin rewriting `user_id` on a membership, and a removed admin's token setting its own row back to active. It breaks the SEC-003 + SEC-029 chain at the delete step; SEC-029 itself stays open.

`npm run test:authz` builds a throwaway local database. Without this migration, 13 attacks succeed. With it, they are blocked and the invite, role change, disable, remove, profile save, team list, ownership transfer and invite activation cases pass at database level. **Not tested:** those flows in the signed-in app.

## How to update this tracker

1. Assign an owner.
2. Move to `Confirmed` or `False Positive` only with saved evidence, and remove `(P)`.
3. Move to `Fixed` when the change is merged **and deployed**, including migrations.
4. Move to `Retested` only after the retest passes. Link the evidence and enter the date.
5. `Accepted Risk` needs a named approver, a reason and a review date.
6. Never reuse an ID. New findings continue from SEC-038.
